## Security Decisions

- Migrations `00001` through `00016` are unchanged.
- Legal consent is user-scoped because it is required before organization creation; existing organization RLS remains unchanged.
- Consent writes use the authenticated Supabase client under RLS. No new service-role path or SECURITY DEFINER RPC was added.
- The database, not the client, sets the consent timestamp and prevents a user from writing another user's consent.
- Publishing revised legal copy requires inserting a new version; existing document and consent records cannot be updated or deleted through ordinary application roles.
- Server-side enforcement is in the callback and dashboard/data-access layer. The proxy intentionally remains an optimistic authentication check and does not perform a database consent lookup.
