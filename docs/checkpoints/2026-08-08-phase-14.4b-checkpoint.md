### Bug: Permission Denied for onboard_user (Root Cause + Fix)

**Root Cause:** `@supabase/ssr` `createServerClient` with cookies configured forwards the authenticated user's session JWT as the `Authorization` header, even when the API key is the `SUPABASE_SERVICE_ROLE_KEY`. PostgREST determines the effective role from the JWT's `role` claim (`authenticated`), not the API key. This meant `onboard_user` RPC executed as `authenticated` (EXECUTE revoked in migration 00010), not `service_role` (EXECUTE granted in 00011).

Both provisioning paths were affected: the auth callback route and the dashboard layout safety net.

**Fix (commit `f200dc1`):** Added `createServiceAdminClient()` to `src/lib/supabase/server.ts` — a `createServerClient` with empty cookie implementations (`getAll: () => [], setAll: () => {}`). With no session cookies loaded, the library sends the service_role key as the `Authorization` header. RPC calls execute as `service_role`. Updated both call sites: callback route `onboardNewUser()` and dashboard layout safety net.

**Migrations:** 00001–00016 untouched. No database privilege changes.
