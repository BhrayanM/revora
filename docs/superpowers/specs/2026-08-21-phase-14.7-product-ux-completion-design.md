# Phase 14.7 Product UX Completion Design

**Date:** 2026-08-21
**Status:** Approved
**Scope:** Protected Revora product experience only

## Goal

Finish the protected Revora application as a coherent, responsive,
keyboard-accessible, portfolio-ready product surface. Phase 14.7 turns the
remaining truthful product capabilities into usable UI, removes dead or
misleading controls, and preserves every security, tenant, provider, and
migration boundary completed through Phase 14.6G.

## Approved Product Boundary

Phase 14.7 delivers:

- recognizable local branding for all ten integration providers;
- a responsive and accessible integration-card hierarchy;
- organization-scoped global lead search with keyboard access;
- a read-only activity center backed by real CRM and automation activity;
- a bounded Google Calendar workspace for upcoming appointments and explicit
  appointment creation;
- a standalone AI Insights view derived from persisted lead qualifications;
- validated workspace language and IANA timezone selectors;
- removal of dead, misleading, or inaccessible controls and `Soon` labels;
- a consistency pass across dashboard, analytics, leads, pipeline, automation,
  settings, team, profile, notifications, Calendar, and AI Insights;
- deterministic product-UX tests and visual QA at mobile, tablet, and desktop
  widths in both themes.

Phase 14.7 does not deliver:

- two-way Chat, SMS, WhatsApp, voice, or other messaging transport;
- Twilio mutations, number purchase, or paid provider operations;
- inbox reading, Gmail campaigns, or bulk communication;
- a new notification persistence/unread model;
- full UI localization or translated product copy;
- drag-and-drop pipeline changes;
- landing-page, pricing, legal-copy, or production-infrastructure redesign;
- deployment, push, credentials, live provider mutations, or production
  readiness claims.

Chat is intentionally removed from primary navigation. A chat product would
require an approved delivery channel, consent and opt-out rules, sender
identity, retention policy, and likely new persistence. It remains deferred
outside Phase 14.7 instead of appearing as a non-functional promise.

## Information Architecture

The protected navigation becomes:

- Main: Dashboard, Analytics
- Sales: Leads, Pipeline, Calendar
- AI: AI Insights
- Automation: Automation
- Settings: Settings, Team, Profile

Notifications remain available from the top navigation as an activity center.
Global Search becomes the primary top-navigation interaction and opens with
`Ctrl+K` or `Cmd+K`. No primary navigation item remains disabled or labeled
`Soon` after the phase.

The sidebar owns one responsive state model:

- mobile open/closed;
- desktop expanded/collapsed;
- content offset synchronized with the desktop state;
- close on route selection, overlay click, or Escape;
- focus moved into an opened mobile sidebar and returned to the menu trigger on
  close;
- off-canvas interactive descendants excluded from keyboard navigation.

## Integration Provider Branding

The ten provider cards use trusted, package-local SVG brand data rather than
remote images:

- HubSpot
- GoHighLevel
- n8n
- Zapier
- Make
- Slack
- Twilio
- Tally
- Google Calendar
- Gmail

Provider marks are decorative beside an existing text name, so they are hidden
from assistive technology. Brand color is limited to the icon tile; card
status, buttons, and focus indicators continue using Revora semantic tokens.
The UI never depends on a remote logo host, tracking pixel, or runtime image
request.

Integration cards use a stable hierarchy:

1. provider mark, name, and health state;
2. one-line capability and safe external account label;
3. primary connection action or compact connected actions;
4. inline live result for Test, Connect, and Disconnect;
5. documentation as a secondary external link.

At narrow widths actions wrap below the identity block and remain at least
44px high. Pending actions disable conflicting controls and announce their
result through a polite live region. No credentials or provider response
bodies enter the DOM.

## Global Lead Search

Global Search is a lead finder, not an unsupported cross-product search.

### Interaction

- The top-nav control is a real button with the shortcut hint.
- It opens an accessible dialog with an immediately focused search input.
- Queries run after at least two non-whitespace characters.
- Results show lead name, company, email when present, pipeline/status context,
  and a direct link to the lead.
- Arrow keys move through results, Enter opens the active lead, and Escape
  closes the dialog.
- Mobile uses the same dialog as a full-width sheet-like surface.
- Empty, loading, short-query, failure, and no-result states are explicit.

### Server boundary

The server action re-authorizes `leads.read` for the active organization on
every request. It accepts at most 80 normalized Unicode characters and returns
at most eight safe result DTOs. It never accepts an organization ID from the
client.

Name, company, email, and phone searches are performed through separately
scoped Supabase filters, merged and ranked on the server, which avoids placing
untrusted input inside a PostgREST `.or(...)` expression. Every query includes
the authorized organization ID and a small result limit.

## Activity Center

The existing `/notifications` route becomes a truthful read-only Activity
Center. It does not claim unread counts, delivery guarantees, or preference
storage that do not exist.

The server re-authorizes `dashboard.read`, then loads a bounded recent window
from organization-scoped existing sources:

- CRM lifecycle notes in `conversations`;
- `automation_executions`, emphasizing failed or retried provider work;
- safe integration audit events such as connection, degradation, and
  reauthorization changes.

Rows are transformed into a common safe DTO, sorted by timestamp, and capped.
Lead activity links to the corresponding lead. Provider entries expose only
provider, safe event category, status, and time. Credential data, raw metadata,
payloads, provider bodies, recipient details, and event contents are excluded.

The Settings notification placeholder and Profile preference placeholder are
removed. Settings explains that in-app activity is always available and that
external exact-HOT alerts are managed through the Slack integration; it does
not present non-persistent switches. The decorative profile camera button is
removed until avatar storage is actually designed.

## Calendar Workspace

`/calendar` becomes an active workspace backed by the Phase 14.6F Google
Calendar grant.

### Read path

- Re-authorize `leads.read` for the active organization.
- Require a healthy Google Calendar connection.
- Use the existing fixed Google Calendar origin, bounded token lifecycle,
  redirect rejection, 15-second timeout, and 64 KiB response limit.
- Request at most 25 single events from the primary calendar for a bounded
  upcoming window.
- Project the provider response to event ID, summary, start, end, and optional
  location only; do not persist event bodies.

The page shows an agenda list with timezone-aware formatting, a clear empty
state, and a Settings connection action when Calendar is unavailable or needs
reauthorization.

### Create path

- Re-authorize `leads.write` for the active organization.
- Optionally select one organization-scoped lead with an email address.
- Accept summary, optional description/location, start, end, timezone, and the
  selected lead email.
- Call the already bounded `createGoogleCalendarAppointment` operation from
  Phase 14.6F exactly once.
- Never retry an ambiguous provider mutation automatically.
- Return a normalized success/error result, revalidate Calendar, and never
  expose Google response bodies.

The form uses the organization's validated timezone by default. Calendar
connection management remains protected by `integrations.manage`; scheduling
does not grant access to integration credentials.

## AI Insights

`/insights` is a real read-only decision surface derived from persisted lead
qualification data. It does not issue automatic model requests or manufacture
insights.

The server re-authorizes `analytics.read`, loads only organization-scoped
leads, and derives:

- qualified and unqualified counts;
- HOT, WARM, and COLD distribution;
- average persisted AI score;
- a prioritized queue ordered by temperature, score, and recency;
- safe signals, risks, summary, and next action already stored in each lead's
  qualification metadata.

Each item links to the lead detail where authorized qualification can already
be rerun. Missing or malformed qualification metadata is treated as
unqualified data, never rendered as raw JSON, and never causes the page to
fail.

The Dashboard AI card links to this view and reports only persisted results.
The old `Soon` badge is removed.

## Workspace Preferences

### Language

The free-text language field becomes a native accessible selector with the
initial supported preference values:

- `en-US` — English (United States)
- `es-419` — Español (Latinoamérica)

The setting is explicitly a workspace formatting/content preference; Phase
14.7 does not claim complete translated UI. Legacy `English (US)` and Spanish
labels are normalized to canonical codes when displayed or saved.

### Timezone

The free-text timezone field becomes a native accessible selector populated
from `Intl.supportedValuesOf("timeZone")` with a deterministic fallback list
for runtimes that do not expose that API. The saved value must be a supported
IANA timezone and is validated again on the server with `Intl.DateTimeFormat`.

### Save contract

The server action:

- re-authorizes `organization.settings.manage`;
- validates organization name, optional HTTPS website, optional contact email,
  language, and timezone;
- trims bounded strings;
- merges safe settings without accepting arbitrary keys;
- returns field-safe errors and never writes invalid values.

No schema change is required because organization settings already use the
existing JSON settings column.

## Shared Visual and Accessibility Pass

The phase keeps Revora's restrained neutral system and improves consistency
rather than redesigning the brand.

Shared product rules:

- one page-header pattern for title, description, and actions;
- one empty-state pattern with a real next action when available;
- route-level skeletons that resemble their final content;
- recoverable errors with a retry or safe navigation action;
- success/error feedback announced without color-only meaning;
- visible keyboard focus on every interactive element;
- no nested buttons/links, clickable non-buttons, or dead controls;
- tables retain semantic headers and keyboard-operable sorting;
- horizontal overflow is deliberate on Pipeline and data tables;
- cards and action rows wrap without overlap at 375px;
- no motion required to understand state and reduced-motion preferences are
  honored;
- timestamps use the validated workspace locale/timezone where the server has
  the organization context.

The pass audits Dashboard, Analytics, Leads, Pipeline, Automation, Settings,
Team, Profile, Activity Center, Calendar, and AI Insights. It does not rewrite
working RBAC, organization switching, integration logic, or security flows
merely for stylistic uniformity.

## Error and State Model

Every new surface distinguishes:

- initial loading;
- empty data;
- permission absence;
- provider not connected;
- provider reauthorization required;
- recoverable provider/network failure;
- validation failure;
- successful completion.

Client messages use stable Revora copy. Server logs may include a safe
operation label and normalized code, but never credentials, search contents,
lead personal data, event descriptions, raw metadata, or provider bodies.

## Authorization and Tenant Isolation

- Global Search: `leads.read`
- Activity Center: `dashboard.read`
- Calendar read: `leads.read`
- Calendar create: `leads.write`
- AI Insights: `analytics.read`
- Workspace preferences: `organization.settings.manage`

Every server operation derives the active organization from the authenticated
membership context. Client-provided organization IDs are rejected by design.
Provider credentials remain encrypted, server-only, and absent from safe DTOs.
Existing RLS remains a second tenant boundary.

## Data and Migration Boundary

Phase 14.7 is designed to reuse existing tables and organization settings. No
schema migration is expected. Migrations `00001` through `00035` remain
byte-for-byte immutable. If implementation proves a schema change strictly
necessary, work stops before adding it and a new consecutive migration must be
separately justified.

## Verification

The phase adds a deterministic `test:product-ux` gate covering:

- provider-logo coverage for all ten provider IDs;
- no remaining protected-product `Soon` placeholder;
- search normalization, limits, ranking, tenant-derived action boundary, and
  safe result projection;
- activity DTO projection and exclusion of unsafe metadata;
- Calendar list bounds, provider response projection, permission boundaries,
  and one-shot appointment creation;
- AI insight parsing, ranking, malformed metadata, and empty data;
- canonical language and IANA timezone validation, including server rejection
  of forged values;
- navigation destinations, dialog semantics, and critical accessibility
  contracts;
- reduced-motion and responsive shell contracts.

The global closure gate runs:

- `npm.cmd run test:product-ux`
- `npm.cmd run test:integration-e2e`
- `npm.cmd run lint`
- `npm.cmd run typecheck`
- `npm.cmd run build`
- `npm.cmd audit`
- `git diff --check`
- targeted Prettier checks
- migration immutability comparison for `00001`-`00035`
- changed-file credential and private-data scan

Visual QA covers widths 375, 768, and 1440 pixels; light and dark themes;
keyboard-only navigation; focus return; search shortcut; sidebar behavior;
empty, loading, error, success, provider-disconnected, and populated states.

## Completion Criteria

Phase 14.7 is locally complete only when:

1. all approved modules above are implemented and linked from truthful
   navigation;
2. Chat is documented as deferred and absent from primary navigation;
3. no dead product control or protected-product `Soon` label remains;
4. no prior migration, provider security boundary, or organization-isolation
   behavior regresses;
5. deterministic, static, build, dependency, and visual gates pass;
6. local commits and a final handoff identify any external-only limitation;
7. no push, deployment, purchase, credential use, or live provider mutation
   occurs.

Phase 14.8 remains the production infrastructure and release-readiness phase.
